# SimProbe

**AI 驱动的自动驾驶仿真场景探索与局部能力边界分析平台原型**

SimProbe 面向自动驾驶仿真数据闭环中的一个核心问题：

> **当版本回归中发现异常后，如何进一步探索场景参数空间，并找到风险状态发生变化的局部边界？**

平台从 Daily 回归报告出发，将异常问题自动转化为可执行的场景探索任务。  
Qwen 负责场景语义理解、候选探索因素规划，以及在首轮探索信息不足时的高层重规划；确定性 Python 引擎负责参数生成、约束检查、仿真执行、状态评估、敏感度分析和局部边界判定。

最终，SimProbe 将单个问题转化为一条可复查的探索链路：

```text
问题
  ↓
场景理解
  ↓
探索因素
  ↓
参数空间
  ↓
探索样本
  ↓
状态变化
  ↓
局部边界
```

从而回答：

> **在当前场景条件下，哪些参数变化会使系统在 PASS / HIGH_RISK / FAIL 之间发生状态转换？**

---

## 核心设计

SimProbe 不追求“全链路 LLM 化”。

设计原则是：

> **语义理解和开放式策略规划交给 LLM；数值计算、约束、仿真、评测和边界判定交给确定性程序。**

### AI Planning Layer

Qwen3.8-Flash 负责：

- 场景语义理解
- 关键参与者与交互关系提取
- 候选探索因素规划
- 基于确定性指标证据的条件触发式重规划

### Deterministic Execution Layer

Python 负责：

- 参数合法范围与场景约束
- 参数空间生成
- 确定性采样
- 本地运动学仿真
- PASS / HIGH_RISK / FAIL 状态判定
- 参数敏感度分析
- 局部状态转换区域检测
- 定向细化
- 最终边界事实生成

这种拆分保证了开放式规划能力，同时避免让 LLM 直接决定数值和最终事实。

## 工作流

```text
Daily 回归问题
      ↓
候选任务识别
      ↓
智能场景理解
      ↓
探索因素规划
      ↓
参数空间构建
      ↓
粗粒度场景探索
      ↓
仿真与状态评估
      ↓
参数敏感度分析
      ↓
自适应重规划（条件触发）
      ↓
局部状态转换区域发现
      ↓
定向边界细化
      ↓
边界结论与场景资产沉淀
```

一个 Daily Report 可以产生多个候选任务。  
每个种子场景独立创建一个 Run，多个 Run 由 Batch 汇总。

## 核心能力

### 1. 从回归问题自动生成探索任务

用户上传 Daily 回归报告后，系统自动识别值得进一步分析的异常场景。

正式示例输入仅包含 8 个事实字段：

- 用例 ID
- 上一版本
- 当前版本
- 上一版本结果
- 当前评测结果
- 严重度
- 问题描述
- 关键指标

系统自动推导：

- 结果变化
- 评测说明
- 默认种子场景映射

LLM 不参与候选资格判断。

---

### 2. 智能场景理解

Issue Interpreter 根据问题描述和可用指标提取：

- 场景类型
- 关键参与者
- 交互关系
- 候选探索因素

例如，在高速汇入场景中，系统可以识别：

- 自车
- 目标车道后车
- 相对接近关系
- 自车速度、后车速度、后向间距、汇入时长等候选因素

结构化输出采用受约束的 Schema 与参数白名单，避免模型自由生成不存在的参数。

---

### 3. 参数空间自动构建

所有场景参数、单位、合法范围和约束统一由 `Scenario Registry` 管理。

当完整组合数量较小时：

```text
FULL_CARTESIAN
```

执行完整参数组合。

当候选空间过大时：

```text
DETERMINISTIC_MAXIMIN
```

使用确定性的空间覆盖策略控制样本规模，并保持参数空间覆盖。

当前单轮粗粒度探索场景数上限为 128。

---

### 4. 本地运动学仿真与状态评估

当前 Demo 使用：

```text
LocalKinematicSimulator + EvaluationEngine
```

对生成场景执行本地运动学仿真。

评估指标包括：

- 碰撞
- 最小碰撞时间（TTC）
- 最小纵向间距

系统输出：

```text
PASS / HIGH_RISK / FAIL
```

所有状态判定由确定性 Python 完成，Qwen 不参与评测结果计算。

---

### 5. 参数敏感度分析

当已有探索样本足够时，系统在控制其他参数不变的条件下，分析单一参数变化与风险状态之间的局部趋势。

输出包括：

- 趋势方向
- 方向一致证据
- 可追溯样本对

敏感度分析用于提供**局部方向证据**，而不是跨参数的重要性排名。

---

### 6. 条件触发的自适应重规划

如果首轮探索只得到单一状态，例如：

```text
ALL FAIL
```

系统不会直接结束。

流程会变成：

```text
首轮探索
   ↓
单一状态
   ↓
MetricSensitivity 提取方向证据
   ↓
Qwen 选择值得继续探索的因素
   ↓
Python 根据合法方向生成新参数值
   ↓
第二轮探索
```

其中：

> **Qwen 决定“重点探索什么”；Python 决定“具体探索哪些数值”。**

最多执行两轮粗粒度探索。

---

### 7. 局部能力边界分析

当相邻样本出现状态变化后，系统寻找局部转换区域并进行定向细化。

最终边界结论包括：

- 边界参数
- 固定条件
- 粗粒度转换区间
- 精化区间
- 状态变化顺序
- 区间缩减程度

示例：

```text
固定条件：
自车速度 = 100 km/h
前车速度 = 75 km/h
初始纵向间距 = 50 m

边界参数：
前车制动加速度

局部状态转换区间：
-4.062 ~ -3.875 m/s²

状态变化：
FAIL → HIGH_RISK → PASS
```

产品层可理解为“局部能力边界”，严格来说，当前 Demo 输出的是：

> **本地运动学仿真下、固定条件与已采样区间内的局部状态转换边界。**

不会将不同固定条件下的结果合并成全局规则。

## 产品界面

SimProbe 当前提供五个主要入口：

- **总览**：运行状态与近期边界发现
- **场景资产**：种子场景、粗粒度场景、细化场景
- **运行记录**：单次探索任务、执行链路和边界结果
- **评测分析**：边界结论、风险切片、参数敏感度和样本分布
- **场景探索**：上传 Daily Report、筛选候选任务并执行探索

## 场景资产与运行资产

SimProbe 将探索过程中的中间结果作为可复查资产保留。

单个 Run 可包含：

```text
Seed
  ↓
Coarse Cases
  ↓
Transition Anchors
  ↓
Fine Cases
  ↓
Local Boundaries
```

生成的场景不会自动写回正式种子场景库，从而避免一次探索产生的大量派生场景直接污染长期回归资产。

生产化场景下，可以进一步扩展：

```text
高价值场景候选
      ↓
规则 / 人工审核
      ↓
正式回归场景库
```

当前版本不实现该场景晋升机制。

## 快速开始

### 1. 创建 Python 3.11 虚拟环境

Windows PowerShell：

```powershell
py -3.11 -m venv .venv
```

### 2. 安装依赖

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 3. 启动平台

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

默认配置使用 Mock Provider，因此无需 API Key 即可启动平台和查看已有演示资产。

参考 `.env.example` 在本地配置：

```env
LLM_PROVIDER=qwen
DASHSCOPE_API_KEY=
```

请仅在本地 `.env` 中填写实际 API Key，API Key 不应提交到 Git 仓库。

## 当前能力边界

SimProbe 当前是一个**仿真探索与局部边界分析平台原型**，并不是商业级自动驾驶仿真云平台。

当前版本：

- 使用简化的本地运动学仿真；
- 没有运行真实 ADS Planner / Controller；
- 没有接入 VTD、WorldSim、CARLA 等高保真仿真后端；
- 不提供云任务调度、数据库、多租户或权限系统；
- 所有边界均限定在具体固定条件和已采样区间内；
- 不应解释为真实车辆或真实自动驾驶算法的全局能力边界。

如果未来接入真实仿真 Backend，现有的：

```text
任务识别
→ 场景理解
→ 参数探索
→ 敏感度分析
→ 自适应重规划
→ 边界检测
```

这套上层框架可以继续复用。
